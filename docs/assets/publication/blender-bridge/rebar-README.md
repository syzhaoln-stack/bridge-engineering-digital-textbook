# 一片 T 梁里的钢筋与孔道

钢筋放在第二跨第一片边梁 `C1_S2_Girder1` 内，轴线 y=-11.65 m，梁端 x=30.35～59.65 m，梁高 2.00 m。它是帮助辨认构造关系的教学布置；原案例也将这组钢筋标为“representative non-design rebar cage”，没有复现公开图册的完整配筋表。

## 为什么要改

原最终 `.blend` 的曲线和求值网格均在修改前实测，记录在 `records/rebar-source-measured.json`：

1. 原箍筋顶部中心线 z=12.36 m，直径 12 mm，其最高实体外缘 z=12.366 m；原上排 φ20 mm 纵筋中心 z=12.42 m，最低外缘 z=12.410 m，确实处于箍筋外。
2. 原腹板纵筋与箍筋侧肢都在距梁轴 ±0.065 m 处，实体互相穿插。原箍筋马蹄折点还局部穿出混凝土。
3. 原外侧两条孔道横向偏置 ±0.13 m，加上 31 mm 半径后超出了部分 200 mm 厚腹板。

修正保留一组窄的腹板闭合箍，在上部围住架立筋；翼缘的四根纵向分布筋另配翼缘联系筋。主箍下部提前向内收，第二排下部钢筋随之内收。腹板四根构造筋改用教学 φ12 mm，并错开箍肢。三条孔道改为腹板中央竖向错层，以消除穿出混凝土的问题。全部中心线、半径、位置变化和适用范围在 `records/rebar-geometry-contract.json`。

公开图册第 8 页 §6.3.2(3) 提出梁体钢筋最小净保护层 30 mm。这里用钢筋实体外缘与混凝土实体检查所列保护层和包含关系，不能用中心线之间的距离代替净保护层。

**闭合路径只表达包围关系。** 这不是可直接加工或施工的钢筋详图，没有设计弯钩、弯曲半径、搭接和锚固长度，也没有完成最小施工净距、承载力、疲劳、张拉与端部锚固区验算。三条孔道的线形和端块同样属于教学布置；不能从本模型推断原桥实际的预应力筋束数量或配筋设计。

独立检查读取了最终 GLB 的实际网格，372 项主体尺寸、981 项钢筋几何、4 项元数据检查均通过，见 [检查摘要](records/independent-check.json) 和 [钢筋详细检查](records/rebar-independent-audit.json)。这些项按对象展开，并非 1357 项工程设计验算。箍筋外包络最小净保护层约 34 mm；普通纵筋约 46 mm；孔道距混凝土外表面约 69 mm，孔道到腹板纵筋的最小几何净隙约 9 mm。保护层采用最终网格及密集半径采样，仍受采样范围和模型假设限制；9 mm 的正间隙也不证明满足浇筑与施工净距要求。

最后修正了新增架立筋和 143 道翼缘联系筋复制后继承的对象 ID。该步骤只改节点标识，几何二进制块未变化，见 [ID 修补记录](records/rebar-id-metadata-patch.json) 和 [独立等价性检查](records/rebar-metadata-independent-check.json)。两张钢筋渲染和原六张桥梁渲染均保持既定几何。

## 重建

程序为 `scripts/blender-bridge/repair_rebar.py` 和 `render_rebar.py`。通过主脚本的 `--rebar-only` 参数只导出更新 GLB 并渲染这两张钢筋图；追加 `--render-only` 可保留已有 GLB。程序只修改内存中的派生模型，原 `.blend` 不会被保存覆盖。两张静态图的半透明材质和剖切副本不进入 GLB。
